# Pulse — центр управления AI и сервером

Рабочий сервис на сервере `mysvcode`, приложение в `/dashbord`, systemd unit `pulse-dashboard.service`. Слушает **только `127.0.0.1:8765`**. Сбор данных и экран обновляются каждые 15 секунд независимо от открытого проекта и подключённого браузера. Лимиты Codex запрашиваются раз в 5 минут, без вызовов модели.

## Как открыть

При подключении к этому серверу через VS Code Remote SSH откройте вкладку **Ports / Порты**, добавьте порт **8765** и откройте его в браузере. Не переводите порт в публичный режим. В обычном SSH можно использовать `ssh -L 8765:127.0.0.1:8765 USER@SERVER`, подставив существующее подключение к серверу, затем открыть `http://127.0.0.1:8765` на своём компьютере. Если локальный порт занят, используйте `-L 18765:127.0.0.1:8765` и открывайте локальный порт 18765.

Публичный домен и HTTPS-прокси в этом релизе не настраивались. В приложении нет собственной аутентификации, поэтому прямой публичный доступ не предусмотрен.

## Возможности

- Статистика Codex и Claude Code за сегодня, 7, 14 или 30 дней: токены, сессии, вход/выход, чтение и запись кэша, график и доступная текстовая таблица. Даты группируются в `Asia/Kamchatka` (UTC+12).
- Лимиты Codex через официальный локальный app-server и резервно из журнала. Отображаются источник, время снимка, остаток и время сброса. Снимок старше 10 минут помечается устаревшим; после указанного сброса остаток не вычисляется до свежих данных.
- Лимиты Claude (окна 5 часов и 7 дней) собираются автоматически раз в 5 минут из аккаунта Claude: `GET https://api.anthropic.com/api/oauth/usage` с ключом входа, который Claude Code хранит в `~/.claude/.credentials.json`. Платных запросов к модели нет. Это **недокументированный** адрес, которым пользуется сам Claude Code; его формат может измениться без предупреждения. Ключ только читается и отправляется исключительно на этот адрес; в БД, API и журналы он не попадает. Pulse никогда не обновляет вход сам: обновление ротирует ключ и могло бы разлогинить Claude Code. Если ключ истёк (Claude Code давно не использовался), источник показывает «Вход Claude истёк», а последний снимок помечается устаревшим; после любого использования Claude Code сбор продолжится. Отключение: `PULSE_CLAUDE_CREDENTIALS=disabled`.
- Автопоиск адреса лимитов Claude. Если адрес отвечает 404/405/410 или ответ больше не содержит окон `five_hour`/`seven_day`, Pulse ищет новый адрес в самой свежей установленной программе Claude Code (`~/.vscode-server/extensions/anthropic.claude-code-*/resources/native-binary/claude`, `claude` в PATH, `~/.local/bin/claude` или `PULSE_CLAUDE_PROGRAM`). Кандидаты — пути `/api/oauth/...` со словами usage/utilization/limit/quota, ближайшие к `fetchUtilization`; проверяются максимум три. Ключ отправляется только на `https://api.anthropic.com/api/oauth/...`, другие хосты из программы не используются. Найденный адрес сохраняется в `data/claude-endpoint.json`. Одна версия Claude Code просматривается один раз; следующий поиск — после обновления расширения. Пока новый адрес не найден, источник показывает «Адрес лимитов Claude изменился». Если Anthropic поменяет формат ответа, а не только адрес, автопоиск не поможет: нужна правка кода. Для сброса удалите `data/claude-endpoint.json`. Status line Claude Code (`scripts/claude_statusline.py`) остаётся резервным источником, если Claude Code запускается в терминале.
- Подтверждённое время задач Codex: объединение интервалов с началом и концом, пересечения параллельных задач считаются один раз. Это не рабочее время человека и не сумма времени всех агентов. Незавершённые задачи не включаются в длительность. Открытая задача без свежих событий отмечается как неопределённая.
- Подтверждённое время задач Claude Code: задача начинается с запроса человека (`promptId`) и завершается ответом модели со `stop_reason` `end_turn`. Результаты инструментов, служебные записи и субагенты (`isSidechain`) новых задач не создают; токены субагентов учитываются в расходе. Если следующий запрос пришёл до завершения, предыдущая задача считается прерванной и длится до её последнего события. В обзоре время Codex и Claude объединяется, пересечения считаются один раз.
- CPU (средняя загрузка между замерами), RAM, диск с данными Pulse и uptime хоста. Эти показатели не равны занятости AI или пользователя.
- Статусы источников, время последнего успешного сбора, ошибки чтения и пропуски. Нет вымышленных проектов, стоимости, трафика или внешних интеграций.

## Данные и расчёты

`pulse/store.py` читает новые полные строки JSONL по курсору; неполная строка остаётся до следующего цикла. Курсоры и нормализованные записи хранятся в `data/pulse.sqlite3` (SQLite WAL). Перезапуск не теряет импортированную историю. Версия схемы хранится в `PRAGMA user_version`; при обновлении схемы курсоры сбрасываются и журналы перечитываются, а дедупликация не даёт задвоить расход. После удаления журналов уже импортированные значения сохраняются. Изменение/ротация файла запускает повторное чтение с дедупликацией.

Для Codex используются приращения `total_token_usage` в `event_msg/token_count`, обнуление счётчика начинает новый сегмент. Параллельные `token_usage_record` не суммируются с этими событиями. Повторная копия события не добавляет расход. Для Claude записи одного `message.id` объединяются по максимальным счётчикам, чтобы учитывать повторные или обновлённые блоки ответа. Кэш уже включён во вход; дополнительно к общему числу токенов он не прибавляется. Это объём обработки, а не оплаченные токены, цена подписки или процент её лимита.

Хранятся только числовые показатели, времена, состояния источников и хешированные идентификаторы. Содержимое переписок, названия проектов, токены доступа и ключи не сохраняются в БД и не отдаются API. Авторизацией Codex занимается его штатный app-server. Единственный читаемый файл авторизации — ключ входа Claude Code, только для запроса лимитов (см. выше). Загрузка истории ограничена имеющимися журналами этого пользователя на этом сервере. Неподдерживаемые изменения форматов, удалённые до первого импорта файлы, другие пользователи и другие машины могут давать неполное покрытие.

## Автоперезапуск

- `Restart=always` и `StartLimitIntervalSec=0`: после падения или любого завершения сервис перезапускается через 5 секунд, без ограничения числа попыток.
- `Type=notify` и `WatchdogSec=180`: сервис сообщает systemd о готовности, а сборщик подаёт сигнал после каждого цикла и каждого прочитанного журнала. Если сигналов нет 3 минуты (зависание или постоянные ошибки сборщика), systemd перезапускает сервис.
- `enabled`: сервис запускается при загрузке сервера.

Проверено: после `kill -9` сервис снова работал через 6 секунд; при заморозке процесса (`kill -STOP`, таймер временно 20 с) сработал watchdog и сервис перезапустился. Число перезапусков: `systemctl show -p NRestarts pulse-dashboard.service`; причины: `journalctl -u pulse-dashboard.service | grep -iE 'watchdog|restart'`.

## Управление

```bash
systemctl status pulse-dashboard.service
systemctl restart pulse-dashboard.service
journalctl -u pulse-dashboard.service --since '10 minutes ago'
curl http://127.0.0.1:8765/healthz
```

Отключение: `systemctl disable --now pulse-dashboard.service`. Исходный unit хранится в `deploy/pulse-dashboard.service`. Приложение использует Python 3.10+ и системную базу часовых поясов, сторонние Python-пакеты для работы не нужны.

Сервис запущен от существующего пользователя `root`, поскольку журналы и установленный Codex принадлежат этому пользователю и находятся в закрытых каталогах. Unit ограничивает запись папкой данных и рабочим каталогом Codex, включает `NoNewPrivileges` и доступ только на localhost. При переходе на отдельного непривилегированного пользователя нужно сначала перенести агентские сессии и авторизацию или выделить отдельный сборщик; просто смена `User=` потеряет доступ к источникам. Не расширяйте права на все домашние каталоги ради мониторинга.

После обновления исходников запустите проверки и перезапустите сервис. Если менялся unit, установите его в `/etc/systemd/system/pulse-dashboard.service`, выполните `systemctl daemon-reload` и перезапуск. Возврат к предыдущей версии исходников с перезапуском сохраняет БД; при будущих несовместимых миграциях потребуется отдельный план восстановления.

## Конфигурация

Настраивается переменными окружения systemd (через `systemctl edit pulse-dashboard.service`):

| Переменная | Значение по умолчанию |
| --- | --- |
| `PORT` | `8765` |
| `PULSE_DATA_DIR` | `/dashbord/data` |
| `PULSE_TIMEZONE` | `Asia/Kamchatka` |
| `PULSE_INTERVAL` | `15`, минимум 5 секунд |
| `PULSE_CODEX_SESSIONS` | `~/.codex/sessions` |
| `PULSE_CLAUDE_PROJECTS` | `~/.claude/projects` |
| `PULSE_CLAUDE_CREDENTIALS` | `~/.claude/.credentials.json`; `disabled` отключает запрос лимитов Claude |
| `PULSE_CODEX_BIN` | Поиск CLI, затем бинарника расширения VS Code; `disabled` отключает RPC |

При изменении папок обновите `ReadWritePaths` unit и параметр `--output` status line Claude. Пути в unit привязаны к текущему серверу. Для ручного запуска остановите постоянный сервис или используйте другой порт: `python3 server.py --port 18765`.

API: `/api/usage?days=1|7|14|30` и `/healthz`. Health возвращает 503 до первой сводки, при сбое или устаревании сборщика. `/api/usage` сохраняет последнюю сводку при сбое с явной отметкой; браузер показывает её как устаревшую.

## Резервная копия и восстановление

Используйте штатный SQLite backup, чтобы получить согласованную копию работающей WAL-базы:

```bash
python3 - <<'PY'
import sqlite3
source = sqlite3.connect('data/pulse.sqlite3')
target = sqlite3.connect('data/pulse-backup.sqlite3')
with target:
    source.backup(target)
target.close()
source.close()
PY
```

Храните копию в закрытом месте. Для восстановления остановите сервис, сохраните текущий каталог `data` отдельно, разверните резервную БД в чистый каталог данных под именем `pulse.sqlite3`, установите права 700 на каталог и 600 на БД и запустите сервис. Не подкладывайте старые WAL/SHM-файлы к восстановленной БД. Snapshot Claude не обязателен для восстановления — он обновится при следующем событии status line.

## Проверки

```bash
python3 -m unittest discover -s tests -v
NODE=$(ls ~/.vscode-server/cli/servers/*/server/node | tail -1)   # node в PATH не установлен
$NODE --check static/app.js && $NODE tests/frontend.cjs
```

| Файл | Что проверяет |
| --- | --- |
| `tests/test_store.py` | Импорт журналов: повторы, копии, обнуления, неполные и ошибочные строки, сохранность истории, отсутствие текста сообщений в БД; задачи Codex и Claude (завершённые, прерванные, открытые, субагенты), миграция схемы; отчёт: периоды, часовой пояс, дни графика, сессии, лимиты, общее время агентов |
| `tests/test_claude_limits.py` | Лимиты из аккаунта Claude: разбор ответа, ключ уходит только на нужный адрес, истёкший вход не используется и не обновляется, 401/403/500, некорректные ответы, цикл сборщика |
| `tests/test_components.py` | App-server Codex на подставном процессе (успех, ошибка, таймаут, завершение), снимок status line, метрики сервера, скрипт status line и его установщик (сохранение настроек, резервная копия, отказ заменять чужую строку), ветка Codex в сборщике |
| `tests/test_api.py` | HTTP: только разрешённые файлы, заголовки безопасности, проверка периода, `/healthz` |
| `tests/test_e2e.py` | Весь дашборд: настоящий сборщик и HTTP-сервер на тестовых журналах обоих агентов, итоговые цифры, отсутствие приватных данных в API и БД |
| `tests/frontend.cjs` | Логика интерфейса с тестовым DOM: итоги, лимиты, время задач, карточки сервера, пустой график, сбои сборщика и сети, выбор периода |

JavaScript-проверки не заменяют просмотр внешнего вида в браузере. Тесты не обращаются к настоящим Anthropic и Codex.

Подробный план и статус работ: [PROJECT_PLAN.md](PROJECT_PLAN.md).

Источники форматов: [Codex app-server](https://learn.chatgpt.com/docs/app-server), [Claude status line](https://code.claude.com/docs/en/statusline); адрес лимитов Claude не документирован. Форматы локальных JSONL сверены с фактическими файлами этого сервера; это менее стабильная интеграция, чем документированные API.
